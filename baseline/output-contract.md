# 审查报告输出格式契约

> 本文件是**硬契约**：所有项目的门禁脚本都按下面的章节标题与字段名解析报告。
> 修改标题文字、字段名或层级，会导致终端统计与「严重项明细」失效。**不要随意改动本文件。**

## 报告结构

报告为 Markdown，按严重度分三级章节，顺序固定为 严重 → 建议 → 可选。

### 严重

**仅当确实存在严重问题时才输出本章节**；没有任何严重问题时整节省略，不要写“无”或解释性文字。

严重级别定义：可能导致 bug、崩溃、数据丢失、安全漏洞、隐私泄露；注释乱码 / 编码问题（如 `???`、`�`、`锟斤拷`）也按严重处理。

每条问题固定使用下面三行字段：

- **问题描述** — 一句话说明问题与影响
- **文件位置** — 相对路径:行号
- **修改建议** — 具体改法，必要时附代码示例

### 建议

推荐优化，改善可维护性 / 性能 / 跨端兼容性。

- **问题描述** — ...
- **文件位置** — 相对路径:行号
- **修改建议** — ...

### 可选

可改可不改，提升代码质量。

- **问题描述** — ...
- **文件位置** — 相对路径:行号
- **修改建议** — ...

## 硬性约束

1. 章节标题只能是 `严重`、`建议`、`可选` 三个词，使用 `###` 标题（`##` 亦可）。
2. 不得写变体标题，例如 `### 严重问题`、`### 🔴 严重`、`### 严重性评估`、`### 建议优化`。
3. 字段名只能是 `问题描述`、`文件位置`、`修改建议`，并用 `**` 加粗。
4. `文件位置` 统一写成 `相对路径:行号`，例如 `utils/ble.js:12`；跨多行用 `utils/ble.js:12-18`。
5. 一条问题对应一组三行字段；多条问题依次排列。
6. 三级章节之外的内容（如概述、总结）允许存在，但不会被门禁脚本统计。
